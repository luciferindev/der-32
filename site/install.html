! Install guide
Sticky · Forum: Installation

DER/32 has a real installer now: der32-install. It asks a handful of questions, partitions the disk, installs the system, and makes it boot from both BIOS and UEFI. It can also put XFCE on it.

Pick a medium: A. USB stick (real PCs) · B. ISO (virtual machines, CDs) · C. no install at all. Then run the installer.

Getting the imagesPrebuilt images go on the releases page, built and tested by GitHub Actions. Or build them: make release on a Linux host with about 25 GB free (see building).
A A. USB stick (real hardware)

The USB installer image is a complete live system plus the release sets. Write it to a stick. This wipes the stick.

$ lsblk -o NAME,SIZE,MODEL # find the stick. Twice. $ xzcat der32-0.1-amd64-install.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

On Windows or macOS, any raw image writer works (balenaEtcher, Rufus in DD mode). Boot from the stick. BIOS and UEFI both work, but Secure Boot must be off.

The boot menu's first entry picks the console for you: on BIOS machines the serial port if a terminal answers on it, otherwise the screen; on UEFI machines the screen. Entries 2 and 3 force one or the other.

B B. ISO (virtual machines, CDs)

The ISO is the same live system with the same sets, booting from BIOS or UEFI. In VirtualBox, virt-manager or similar, create a 64-bit “Other” or “NetBSD” machine with 1 GiB of RAM or more and an empty disk of 8 GiB or more, then attach the ISO. With plain QEMU:

$ qemu-img create -f qcow2 der32.qcow2 16G $ qemu-system-x86_64 -accel kvm -m 2048 -cdrom der32-0.1-amd64.iso \ -drive file=der32.qcow2,if=virtio -boot d

A USB stick won't boot the ISO. Use the USB image for that.

! Run the installer

Log in as root with password der32, then:

der32# der32-install

It asks, in this order:

  • Disk: lists the disks it found, with sizes. The disk you booted from is never offered. At least 4 GiB.
  • Host name and time zone, for example America/Boise.
  • Console: screen or serial (the default matches how you're logged in).
  • Swap size.
  • Root password, and optionally a user (added to group wheel, so they can su).
  • DHCP and XFCE (yes/no each). There's no SSH question yet: SSH has a known bug in 0.1.

Then it shows a summary and waits for you to type erase wd0 (with your disk's name). Nothing touches any disk before that. After that it:

  • writes a GPT: a 256 MiB EFI partition, swap, and an FFSv2 root using the rest of the disk;
  • extracts the sets (base, etc, comp, man, misc, text and the DER32 kernel);
  • installs the BIOS and UEFI boot loaders;
  • writes fstab (by partition label), rc.conf, the time zone, the passwords and the user.

Takes a few minutes. Then shutdown -r now, remove the medium, and log in to your new system. The full log is in /var/log/der32-install.log.

X The XFCE option

Say yes to XFCE and the installer adds the X11 sets from the medium, then fetches XFCE and its dependencies from NetBSD's binary package mirror with pkgin. That's a few hundred megabytes, so it needs a working network. When it's done, log in and run:

$ startx

If the download fails, nothing else breaks: the X11 sets are installed and you can add the desktop later with pkgin install xfce4. Want a graphical login? Add xdm=YES to /etc/rc.conf.

Honest statusThe X11 sets and the fallback path are tested automatically. The XFCE download itself can't be, because the test machines have no route to the package mirror. Tell us how it goes on yours.
U Unattended installs

Put the answers in a file and run der32-install -f answers:

DISK=wd0 CONFIRM="erase wd0" HOSTNAME=tortoise TIMEZONE=America/Boise CONSOLE=screen SWAP_MB=1024 ROOT_PWHASH='$argon2id$v=19$...' # from: pwhash 'your password' USERNAME=alice USER_PWHASH='$argon2id$v=19$...' DHCP=yes XFCE=no

Details: der32-install(8). This is how the automated tests install DER/32 on every build.

C C. No install: just run it

The disk images are a ready-made system. In QEMU on the build host:

$ make qemu # serial console on this terminal; Ctrl-A X quits $ make qemu-pc # a window with screen and keyboard

On first login with root / der32, the disk images make you choose a new root password. The live ISO and the USB installer don't, because they're throwaway systems.

! After the first boot
der32# derfetch # admire the tortoise der32# upkg sync # DER/32 packages, from the website der32# upkg install tree nnn der32# pkg_add pkgin # NetBSD's binary packages der32# pkgin install vim git

0 Building the images yourself
$ git clone https://github.com/luciferindev/der-32 $ cd der-32 $ make check # host tools, disk space $ make release # everything below, about 1-3 hours the first time $ ls out/images/ der32-0.1-amd64.img # disk, serial console der32-0.1-amd64-pc.img # disk, screen console der32-0.1-amd64-install.img # USB installer der32-0.1-amd64.iso # live + install ISO

The first build fetches the pinned NetBSD src and xsrc trees (about 2 GB). Stuck? See build problems.
