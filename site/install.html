! Install guide
Sticky · Forum: Installation

DER/32 0.1 doesn't have an installer. There's no wizard, no partition editor and no screen asking you to pick from twelve desktop environments. The disk image is the installed system: you boot it in a VM, or write it to a disk.

Pick one: A. QEMU (recommended) · B. live ISO · C. real hardware. Then do the first-boot checklist.

Before you startPrebuilt images aren't published yet, so you build them first. That takes a Linux host with about 20 GB free and a C compiler, and an hour or two the first time. Arch is the reference host.
0 Step 0: build the images
$ git clone --recurse-submodules https://github.com/luciferindev/der-32 $ cd der-32 $ make check # are the host tools there? $ make release # disk image: out/images/der32-0.1-amd64.img $ make iso # live ISO: out/images/der32-0.1-amd64.iso

A stopped build resumes where it left off: run the same command again. Stuck? See build problems.

A A. Run it in QEMU (recommended)

This is how DER/32 is developed and tested.

$ sudo pacman -S qemu-base # Arch; other distros: install qemu-system-x86_64 $ make qemu # boots a working copy of the image on this terminal

Your changes persist in out/images/der32-run.img, so the release image stays clean. Delete that file to start over. Useful knobs:

Do thisTo get
MEM=2048 make qemumore RAM (default 1024 MiB)
SMP=4 make qemumore CPUs (default 2)
SNAPSHOT=1 make qemuthrow away every change on exit
Ctrl-A, then Xquit QEMU (run shutdown -p now first)
B B. Boot the live ISO

The live ISO runs from read-only media and keeps /etc, /var, /root and /usr/local in RAM, so nothing survives a reboot. That's ideal for a look around.

$ qemu-system-x86_64 -accel kvm -cpu host -m 1024 \ -cdrom out/images/der32-0.1-amd64.iso -boot d \ -display none -serial stdio

Drop -accel kvm -cpu host if you have no /dev/kvm. The ISO is built as a CD image. Booting it from a USB stick hasn't been tested.

C C. Real hardware
Read this twiceWriting the image destroys everything on the target disk. And Genesis talks to a serial port, not your monitor: without a serial cable you'll see the bootloader and then nothing. A VGA-console image is in the works in pull request #1. Real hardware hasn't been tested yet.
$ lsblk -o NAME,SIZE,MODEL # identify the target disk. Twice. $ sudo dd if=out/images/der32-0.1-amd64.img of=/dev/sdX bs=4M conv=fsync status=progress $ sync

Boot it with the BIOS / legacy boot option (the image has an MBR, not UEFI). Connect at 9600 baud. On the Linux side: screen /dev/ttyUSB0 9600.

The image's filesystem is 2 GiB, whatever the size of the disk. Growing it isn't documented yet.

! After the first boot

Log in as root with password der32. Then:

der32# passwd # first. Seriously. der32# echo 'hostname=tortoise' >> /etc/rc.conf der32# hostname tortoise der32# ln -sf /usr/share/zoneinfo/America/Boise /etc/localtime # your zone der32# useradd -m -G wheel alice # a user who may su to root der32# passwd alice der32# upkg sync # DER/32 packages der32# derfetch # admire the tortoise

Want SSH? Add sshd=YES to /etc/rc.conf and run service sshd start. More commands are on the cheat sheet. Your Linux muscle memory mostly works, and where it doesn't, man works.
