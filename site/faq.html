:: General

Is DER/32 a Linux distro?

No. A distro is a kernel plus a pile of packages that someone hopes will get along. DER/32 is one operating system: the kernel and the userland come from one NetBSD source tree, with BSD libc, BSD make, BSD init and rc.d, POSIX sh and FFS. Linux is only the build host. It's very good at compiling BSD.

Is it GNU-free?

No, and that's on purpose. Like NetBSD, the base system ships GCC and binutils as its compiler toolchain. Everything else in base is BSD-licensed.

Why not just run NetBSD?

For a production machine, you probably should. DER/32 is a derivative: it pins one netbsd-10 commit, adds a small patch series (its own identity, kernel config, images, upkg, derfetch) and a slimmer build profile. If you want a hackable BSD where every change from upstream fits in a handful of reviewable patches, that's what it's for.

Isn't this basically MINIX?

No. MINIX is a microkernel teaching system, and these days it mostly lives inside Intel's Management Engine, where you can't log in to it. DER/32 is a monolithic BSD kernel that you can. (Tanenbaum and Torvalds argued about this in 1992. The tortoise abstained.)

Why does uname -s say DER32 but uname -r says 10.2?

The system name is DER/32's own. The release number is NetBSD's, kept on purpose so kernel modules, binary packages and anything else that checks the ABI version keep working. DER/32's own release is in sysctl kern.der32.

:: Hardware

Will it run on my machine?

DER/32 uses NetBSD 10's GENERIC kernel configuration, so it has the same drivers as NetBSD 10 on amd64. NetBSD's hardware lists are the best guide. So far, Genesis has only been tested in QEMU. Reports from real hardware are welcome on the bug tracker.

What are the requirements?

An x86-64 CPU. The automated tests boot with 1 GiB of RAM and 2 CPUs. The disk image is 2 GiB and the live ISO about 525 MiB. The live ISO copies /etc, /var, /root and /usr/local into RAM, so give it some headroom.

I only see a blank screen / no login on my monitor.

The Genesis images use a serial console (com0, getty on tty00). In QEMU that's your terminal. On real hardware you need a serial cable, or the VGA-console image variant that is being worked on in pull request #1.

How do I install it to a disk?

See the install guide. Short version: there's no installer yet. You write the disk image to a disk, and that erases the disk.

:: Using it

What's the login?

root, password der32. Change it right away with passwd. A first-boot password prompt is planned.

How do I get out of QEMU?

Press Ctrl-A, then X. To shut down cleanly first, run shutdown -p now inside DER/32.

Is networking on?

Yes. dhcpcd runs at boot and configures every interface. In QEMU, user-mode networking gives the guest outbound access. SSH is off by default: set sshd=YES in /etc/rc.conf and run service sshd start.

Where's X11 / a desktop?

The Genesis build profile leaves X11 out. DER/32 0.1 is a console system.

How do I change the system's settings?

The NetBSD way: /etc/rc.conf for services, /etc/sysctl.conf for kernel tunables, /etc/fstab for mounts. See the cheat sheet.

:: Packages

upkg or pkgin, which one do I use?

upkg is DER/32's own package manager. It installs from DER/32's signed repositories into /usr/local. pkgin installs NetBSD's pkgsrc binary packages into /usr/pkg. The two never touch each other's files.

Will NetBSD binaries run on DER/32?

They should. DER/32 keeps the NetBSD 10 ABI: same libc, same syscalls, same kern.osrelease.

Does upkg have Super Cow Powers?

No. Ask it about cows and find out what it has instead.

Does upkg run install scripts?

Never. A package is files plus metadata, and that's all upkg installs. Index signatures are Ed25519, package checksums are SHA-256, and an interrupted transaction is completed or rolled back on the next run. Details are in upkg(8).

How do I make my own package?

Write a recipe under ports/<category>/<name>/: a RECIPE file and a build script, then run upkg build <name>. Look at ports/core/lua for a real example, and packages.md for the format.

:: Build problems

make stops right away without an error message.

You're on an old checkout: early versions of the scripts failed silently on a fresh clone. Run git pull and git submodule update --init, then try again.

The tools build fails in gmake / ar.c with GCC 14 or newer.

GCC 14+ defaults to C23 and turns old C warnings into errors, which breaks NetBSD's bundled host tools. Current DER/32 probes the compiler and passes the right flags, and it rebuilds the host tools automatically when those flags change. Run git pull and make release again. You don't need to delete out/.

How much disk does a build need?

About 20 GB: the NetBSD source tree is around 3 GB and out/ around 14 GB after a full release build.

Can I resume a build that stopped?

Yes. Just run the same make target again. Builds are incremental (build.sh -u).

:: Contributing

How do I change something in the OS itself?

DER/32 never edits the NetBSD tree in place. Make your change inside src/ on the der32 branch, commit it there, then regenerate the patch series:

$ scripts/patches.sh status # pinned commit and patch state $ scripts/patches.sh apply # pinned NetBSD + patches/ on branch der32 $ scripts/patches.sh export # write your commits back to patches/

Then open a pull request with the new or changed file in patches/.

What's the license?
